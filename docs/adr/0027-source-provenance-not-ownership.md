# ADR-0027: Keep page provenance in Source instead of labeling every MANIAC-installed page maniac

Status: Accepted
Date: 2026-09-13

## Context

ADR-0017 made the manifest authoritative for MANIAC's ownership of every installed page, regardless of whether its bytes came from an install root, an upstream repository, or synthesis.
The first `list` implementation consequently rendered `Source=maniac` whenever the reachable page matched a manifest entry.
That collapsed two independent facts: who installed the page and who produced its contents.
A vendor page changed from `vendor` to `maniac` after MANIAC copied it onto the manpath, and an upstream page changed from `upstream` to `maniac`, even though neither page was generated or modified by MANIAC.
The manifest already retained the missing distinction in its `tier` field, and `--managed` already expressed the ownership question directly.

## Decision

`Source` reports content provenance.
A manifest entry from the install-root tier renders `vendor`, one from the repository tier renders `upstream`, and one from the synthesis tier renders `maniac`.
Whether a row is managed remains a separate boolean derived from the manifest and continues to drive `--managed`; it is not inferred from the Source label.

Each non-empty Source keyword links to the manpage it describes.
Reachable pages link to the path returned by `man`, install-root availability links to the shipped page, and GitHub repository availability links to the version-pinned file in the upstream repository or the release asset that supplied it.
An upstream Source never exposes MANIAC's cache URI.
Repository discovery records that remote URI beside each materialized cache page, and tier-2 installation retains it in the ownership manifest so the link survives installation.
For repository-tier entries written before that manifest field existed, `list` reuses the normal version-pinned probe to recover the URI without changing the row's installed state.
The Upstream column remains a separate link to the repository rather than the page.
Other Git hosts keep plain Source text until a host-specific adapter can produce an exact-file URI; MANIAC does not guess that URI from a Git clone URL.

## Consequences

Installing an authoritative page no longer erases its provenance in `list`.
`maniac` now means generated by MANIAC rather than merely installed by it, while `--managed` still selects all three managed tiers.
Scripts consuming bare names are unchanged; readers of the human table may see a managed row change from `maniac` to `vendor` or `upstream`.

`ToolRow` carries ownership and the selected page path or remote URI in addition to visible classification fields.
Terminal emulators supporting OSC-8 can open the exact source from the Source cell; unsupported terminals still display the same plain keyword.
Compressed pages may open as files rather than rendered manuals, which is accepted because the link identifies the artifact exactly and the table has no portable URI for invoking `man` itself.
